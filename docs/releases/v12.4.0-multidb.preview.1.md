# Jellyfin multi-database v12.4.0-multidb.preview.1

First preview of the independently maintained [shea786/jellyfin](https://github.com/shea786/jellyfin) fork,
based on stable **Jellyfin 12.4**, upstream commit `83d0d0e7f76e23e2e085c8ff67d28b772d35967d`.
This is a fork preview for testing with recoverable libraries. It is not an official Jellyfin release.

SQLite remains the default supported database. PostgreSQL **16 or later** is the supported external database.
MySQL/MariaDB and SQL Server remain **experimental**; their newer-version advisory jobs do not promote them.

## Image and download

The published image is **Linux amd64 only**:

```sh
docker pull ghcr.io/shea786/jellyfin-multidb:12.4.0-multidb.preview.1
```

Use the image digest in the attached `preview-manifest.json` to pin an immutable deployment. The preview has no
`latest` tag. The container runs as UID/GID **65534:65534**, uses **.NET/ASP.NET Core 10.0.14**, and includes the
matching stable Jellyfin 12.4 web client and **FFmpeg 8.1.3-Jellyfin**. The server API retains version `12.4.0` for
compatibility; identify this fork build by its image tag, digest and OCI version/revision labels.

A complete Docker image is also attached as `jellyfin-v12.4.0-multidb.preview.1-linux-amd64.tar.gz`:

```sh
sha256sum --check SHA256SUMS
gzip -dc jellyfin-v12.4.0-multidb.preview.1-linux-amd64.tar.gz | docker load
```

Download all files listed in `SHA256SUMS` into the same directory before checking them. `preview-manifest.json`
records the source commit, upstream baseline, architecture, image digest and support tiers. Source archives are
available from this release page; ARM images and native installation packages are not part of this preview.

## Running it

Follow the [database operator guide](https://github.com/shea786/jellyfin/blob/v12.4.0-multidb.preview.1/docs/database/README.md) and
[PostgreSQL guide](https://github.com/shea786/jellyfin/blob/v12.4.0-multidb.preview.1/docs/database/postgresql.md). The Compose examples can use the published image by removing the
`build:` section of the Jellyfin service and setting its existing `image:` entry to:

```yaml
image: ghcr.io/shea786/jellyfin-multidb:12.4.0-multidb.preview.1
```

Keep the example's environment, database configuration, health checks, volumes and database service. Use
`JELLYFIN_DATABASE__CONNECTIONSTRING` for the connection string; do not put real credentials in a public report.
For bind mounts or configuration previously written by a root container, give UID/GID 65534 access to the
configuration and cache before starting the preview.

## Upgrade and recovery

1. Stop the source server cleanly. Keep a separate backup of its configuration, database, metadata and media.
   Work on copies for this preview; keep the original server image and backups available.
2. The qualified upgrade starts with **official Jellyfin 12.4 on SQLite**. Start this fork on a copy of that
   configuration and SQLite library, then verify users, watched/resume state, artwork and playback.
3. To move to PostgreSQL, create a Jellyfin backup from the upgraded SQLite instance, prepare a separate target
   PostgreSQL server/configuration, initialize its schema, and follow the operator guide's restore procedure.
   The archive restores data; the target retains its PostgreSQL provider configuration.
4. Back up PostgreSQL with its engine tools before subsequent upgrades, and test recovery. Reverting the image alone
   does not undo schema/data migrations; a rollback requires the matching pre-upgrade database and configuration backup.

Do not switch an existing populated instance to an empty database merely by changing `DatabaseType`. Do not point an
older official image at a database already migrated by the fork. Upgrades from older official versions, from upstream
13.0 development, or between historic development snapshots of this fork have not been qualified for this preview.

## Qualification and limits

The [qualification record](https://github.com/shea786/jellyfin/blob/v12.4.0-multidb.preview.1/docs/database/qualification/v12.4.md) documents green SQLite suites on Ubuntu, macOS and
Windows, the PostgreSQL 16 suite, formatting, and **49 passing real-image assertions**. These cover fresh installs,
an official 12.4 SQLite upgrade, SQLite-to-PostgreSQL restore, matching row counts, watched/resume state, artwork,
direct video streaming, writes after restore, and PostgreSQL backup recovery. The publishing workflow requires all
five supported test/format statuses to pass on the exact tagged commit and verifies its packaged runtime.

The real-image fixture is a small synthetic local library and an API client. Large production libraries, client
applications, plugins, transcoding, hardware acceleration and ARM are outside that fixture. MySQL/MariaDB and
SQL Server are included experimentally but have not received the same installation qualification as PostgreSQL.
